Track List

COGS 108: Analyzing and Forecasting U.S. Rental Price Trends

A data science group project where we explored U.S. rental price trends and used historical rental data to forecast future prices.

Problem

Rental prices vary across cities and change over time, which makes it difficult to understand whether price changes are part of a broader national trend or specific to certain regions. Our project focused on analyzing those changes and testing whether past rental data could help forecast future rental prices.

What I Worked On

I worked on the analysis and visualization side of the project. My main contributions included:

  • Explored rental datasets to understand trends, missing values, and regional differences.
  • Created visualizations to compare rent changes across locations and time periods.
  • Helped interpret forecasting results and explain what the model could and could not show.
  • Contributed to the final written analysis and presentation of findings.

Tools

Python, Jupyter Notebook, pandas, NumPy, matplotlib, Zillow rental datasets, time-series analysis, forecasting methods, and technical writing.

Challenge

The dataset was not perfectly clean. Some locations had missing values, not every region had the same amount of data, and the available data did not always capture every later rent change. That made it important to be careful about how strongly we stated our conclusions.

What I Learned

This project helped me get more comfortable working with real datasets, where the data is messy and the answer is rarely as simple as one number. I also learned how useful visualizations can be for explaining patterns that are hard to see in raw tables.

Status

Completed as a group final project for COGS 108.

CSE 29: Web Chat Server

A systems programming project where I built a small web-based chat server using C, HTTP request handling, and WebSocket communication.

Problem

The project was about building a chat server that could support browser-based communication. Instead of relying on a high-level web framework, the goal was to work closer to the network layer and understand how clients, requests, connections, and real-time messages fit together.

What I Worked On

I worked on the server logic and communication flow. My main contributions included:

  • Handled incoming client connections through C socket programming.
  • Parsed and responded to HTTP requests from the browser.
  • Implemented WebSocket communication for real-time message updates.
  • Tested the server from the command line and browser to debug connection behavior.

Tools

C, socket programming, HTTP, WebSockets, browser testing, command-line testing, buffers, request parsing, and server-side debugging.

Challenge

Because the server was written in C, small mistakes could create confusing bugs. I had to pay close attention to buffers, connection state, request formatting, and how messages moved between the browser and the server.

What I Learned

This project made web servers feel much less abstract. I got to see how HTTP requests, sockets, and real-time communication work underneath the tools that usually hide those details.

Status

Completed as a CSE 29 coursework project.
