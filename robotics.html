TritonDroids MiniAloha Robot

A robotics project where I assembled the MiniAloha robot, brought up its control stack, calibrated its leader-follower arms, and built a browser-based interface for remote operation.

Problem

MiniAloha needed to move from a hardware build into a usable robot platform. Before the team could focus on higher-level autonomy work like simulation and SLAM, the base robot, arm setup, remote access, and browser control interface needed to work reliably.

What I Worked On

I worked across the physical robot, remote access setup, and browser-based control interface. My main contributions included:

  • Assembled the MiniAloha robot and installed the motors on the robot base.
  • Set up and calibrated the leader and follower arms for teleoperation experiments.
  • Configured the Raspberry Pi for remote access and control using Tailscale.
  • Updated the robot control UI so it could be used more easily from the browser.
  • Used FastAPI to serve the control interface and connect the browser UI to the robot setup.

My Role

I worked across the hardware, networking, and software layers of the robot. My focus was making the robot easier to operate: assembling the base, installing motors, calibrating the arms, setting up remote access, and improving the control UI.

Tools

Python, FastAPI, Raspberry Pi, Tailscale, browser-based UI development, motor installation, arm calibration, robot assembly, remote debugging, and team documentation.

Challenge

The main challenge was connecting several layers that all had to work together: physical assembly, motor behavior, arm calibration, network access, and the control interface. A problem could come from hardware, configuration, networking, or software, so debugging required checking the whole system instead of only one part.

Current Focus

The current work is focused on running simulations and implementing SLAM so the robot can move beyond manual control toward more autonomous behavior.

What I Learned

This project taught me how much robotics depends on system integration. A robot is not just code or hardware by itself; it needs reliable physical setup, communication, controls, calibration, and usable interfaces before higher-level autonomy work can really begin.

Playlist Notes

I want to keep building robotics experience because it forces me to think about the whole system, not just one file or one function.
